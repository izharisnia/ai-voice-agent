    Step 01

    API Key Setup & Configuration

    Click API Keys in top header navigation. Input your Gemini API key (Free key available at Google AI Studio).

    STT, TTS, Weather & News run 100% free without paid keys.
    Step 02

    Select Audio Streaming Mode

    In Voice Studio, locate the Real-Time Stream toggle:

    • ON (Recommended): Streams audio chunks in real-time over WebSockets for minimal latency.
    • OFF: Standard HTTP mode where recorded audio is sent upon recording finish.
    Step 03

    Record Your Voice Prompt

    Tap the central Glowing Mic Button or Voice Orb to start listening.

    • Orb pulses in bright magenta/pink while capturing audio.
    • Speak clearly (e.g. "What is the weather in London?").
    • Tap mic button again to finalize turn.
    Step 04

    Native Gemini Tool Execution

    Gemini LLM uses Native Function Calling to execute live tools autonomously:

    • Ask "Weather in Paris" to run live weather API.
    • Ask "Top breaking news" to query Google News RSS.
    Step 05

    SQLite Thread Persistence

    All turns are saved in local SQLite DB (`voice_agent.db`). Click + New Chat in sidebar to start a new thread or load history.

    Backend

    FastAPI (Python)

    What: A modern, high-performance Python web framework.

    Why: It has built-in WebSocket support, automatic API documentation, and async capabilities — perfect for real-time audio streaming.

    How: Serves the HTML frontend, handles HTTP API routes (/agent/chat, /generate-tts), and manages the WebSocket endpoint (/ws/stream-audio) for live audio.

    AI Engine

    Google Gemini Flash LLM

    What: Google's multimodal AI model with native function calling.

    Why: Gemini supports automatic function calling — the model can decide on its own when to call tools like weather or news, without manual routing.

    How: The Python SDK (google-generativeai) registers Python functions as tools. Gemini calls them autonomously during a conversation, then returns the combined answer.

    Transport

    WebSocket Audio Streaming

    What: A full-duplex, persistent connection between the browser and server.

    Why: Regular HTTP uploads the entire recording at once (slow). WebSockets stream binary audio chunks in real-time as you speak, reducing latency.

    How: Browser's MediaRecorder captures mic audio → sends binary chunks via WebSocket → server buffers them → on "stop" event, processes the complete audio through STT → LLM → TTS pipeline.

    STT

    Speech-to-Text (STT)

    What: Converts your spoken voice into text.

    Why: Two options — SpeechRecognition (100% free, zero API keys) or AssemblyAI (higher accuracy, paid key).

    How: Audio bytes are converted to WAV using pydub, then sent to Google's free recognition engine. If an AssemblyAI key is provided, it uses that instead for better quality.

    TTS

    Text-to-Speech (TTS)

    What: Converts the AI's text reply back into spoken audio.

    Why: gTTS is 100% free (no key). Murf API provides premium, natural-sounding voices when a key is available.

    How: gTTS generates an MP3 file saved to static/audio/ and served to the browser. If a Murf key exists, it calls the Murf REST API instead for higher-quality voice.

    Database

    SQLite Persistent Memory

    What: A file-based relational database (voice_agent.db).

    Why: No external database server needed. SQLite runs inside the Python process, stores data permanently on disk, and survives server restarts.

    How: Two tables — sessions (tracks chat threads) and messages (stores every user/assistant turn). The full conversation history is loaded before each LLM call so Gemini has context.

    Implementation Steps

    How this project was built, step by step — in plain English.

    Step 01

    Project Setup & Dependencies

    Created a Python project folder. Installed all required packages using pip:

    • fastapi + uvicorn — the web server
    • google-generativeai — Gemini SDK
    • SpeechRecognition + pydub — free STT
    • gTTS — free text-to-speech
    • python-dotenv — loads .env API keys
    • feedparser — parses Google News RSS
    Step 02

    Database Layer (db.py)

    Built the SQLite database with two tables:

    • sessions — stores each chat thread's unique ID and creation timestamp
    • messages — stores every turn (user/assistant) with a foreign key to the session

    Functions created: init_db(), save_message(), get_history(), clear_history(), and list_sessions_with_preview().

    Step 03

    Speech-to-Text Service (stt_service.py)

    Created a transcribe_bytes() function that:

    • Checks if an AssemblyAI API key exists — if yes, uses it for high-quality transcription
    • If no key, falls back to SpeechRecognition (Google's free engine)
    • Audio bytes are converted to WAV format using pydub for compatibility
    Step 04

    LLM Service with Tool Calling (llm_service.py)

    The brain of the system. Built a call_llm_conversation() function that:

    • Configures the Gemini SDK with your API key
    • Registers two Python functions as native tools: get_weather(city) and get_news()
    • Passes the full conversation history so Gemini remembers past turns
    • Enables automatic_function_calling=True — Gemini decides when to call tools on its own
    • Tries multiple model candidates (gemini-flash-latest, gemini-3.6-flash, etc.) as fallbacks
    Step 05

    Text-to-Speech Service (tts_service.py)

    Created a generate_tts_from_text() function that:

    • Tries Murf API first (premium voices) if a key is provided
    • Falls back to gTTS (Google Text-to-Speech, 100% free)
    • Saves the generated MP3 to static/audio/ and returns the URL for the browser to play
    Step 06

    FastAPI Server & WebSocket (main.py)

    The main server file that wires everything together:

    • HTTP Route (/agent/chat/{session_id}) — accepts uploaded audio, runs the full STT → LLM → TTS pipeline, returns JSON
    • WebSocket Route (/ws/stream-audio) — accepts live binary audio chunks, buffers them, and on "stop" runs the same pipeline over the socket
    • Session Routes — list sessions, get history, clear history
    • Serves static files (CSS, JS, audio) and HTML templates via Jinja2
    Step 07

    Frontend UI (index.html + scripts.js)

    The browser-side interface:

    • Uses MediaRecorder API to capture microphone audio in WebM format
    • Opens a WebSocket connection and streams binary audio chunks in real-time
    • Sends a {"event":"stop"} message when recording ends
    • Receives the AI response (transcript + text + audio URL) and plays the audio automatically
    • Displays chat bubbles, manages sidebar session threads, and handles API key settings
    Step 08

    Run the Server

    Start the entire application with one command:

    uvicorn main:app --reload --port 8000

    Then open http://localhost:8000 in your browser. Click the mic button, speak, and hear the AI respond!

    How It Works — Architecture Flow

    End-to-end data flow from your voice to the AI response.

    Flow 1→3

    Voice Capture → WebSocket Stream

    You click the mic and speak. Your browser captures audio using MediaRecorder, then streams binary chunks over a persistent WebSocket connection to the FastAPI server in real-time.

    Flow 4

    Backend Processing Pipeline

    The server buffers all audio chunks. When you stop recording, it runs: STT (voice → text) → saves to SQLite → sends history to Gemini LLM (which may autonomously call weather/news tools) → generates TTS audio from the AI reply.

    Flow 5→6

    Response → Audio Playback

    The complete response (transcript, AI text, and audio URL) is sent back over the WebSocket. Your browser receives it, displays the chat bubble, and automatically plays the synthesized voice — completing the conversation loop.
